## 1. MCP Server `instructions` Field

**Claude Code:**
- ✔ Injects into system prompt with each session
- ⚠ **~4KB total budget** shared across all connected servers (Issue #43474)
- ⚠ **Silent truncation**: last servers' instructions cut off mid-sentence with no warning
- No documented size cap per-server; budget exhaustion depends on server load order
- Evidence: ctxlayer system-reminder shows truncation: `"...includ… [truncated]"` (Issue #43474)

**Claude Desktop:**
- Undocumented whether instructions are injected; no official guidance found
- No evidence of truncation caps in available docs
- Likely similar to Claude Code but less transparent

**Truncation limit not publicly documented** — reverse-engineered from Issue #43474 as ~4KB total.

---

## 2. Tool Descriptions (200+ Tools)

**Claude Code:**
- **Models with tool search enabled** (Claude 4.5+, Sonnet 4.5+, Haiku 4.5+, Fable 5, Mythos 5):
  - Supports deferred loading via `defer_loading: true` on tool definitions
  - Loads only tool names into context at session start (~0 tokens)
  - Tool search (ToolSearch variant) loads descriptions on demand when Claude searches for tools
  - Threshold: accuracy degrades at 30–50 tools without deferral; tool search mitigates this
  - Docs explicitly recommend deferral for 10+ tools, 10k+ token definitions, or 200+ aggregated tools
  
- **Mechanism**: All tool definitions sent to API server-side; only context injection is deferred via `tool_search_tool_regex_20251119` or `tool_search_tool_bm25_20251119`

**Claude Desktop:**
- **Always loads all tool descriptions eagerly** (~75k tokens for 155 tools per Issue #49073)
- No tool search equivalent documented or working
- **Reported bug** (Issue #49073): "Tool access" UI toggle to defer tools has no effect; MCP tools load regardless
- Desktop does NOT support deferred loading via `defer_loading: true`

**Key distinction**: Tool search is a **Messages API** feature (server-side); Claude Desktop's MCP integration does not surface or use it.

## 3. MCP Prompts

**Claude Code:**
- ✔ Rendered as slash commands: `/mcp__&lt;server&gt;__&lt;prompt&gt;` format
- Documented in CLAUDE.md system-reminder and MCP reference

**Claude Desktop:**
- ✗ No evidence of MCP prompt rendering as UI elements or slash commands
- Not documented in public docs

## 4. MCP Resources

**Both clients:**
- ✗ **Do NOT proactively read** MCP resources
- Resources only read when:
  - User explicitly calls `resources/read` tool
  - User attaches a resource via `@` mention (Claude Code feature)
- **Documented issue** (typescript-sdk #686): "Claude Desktop doesn't use resources of my MCP server" — Desktop calls `resources/list` but never reads them to answer questions

## 5. Anthropic Guidance on Reliable Model Workflows

**No documented best practice** for forcing a model to follow a sequence (e.g., "always fetch playbook before calling tool X").

**Patterns observed in the wild:**
- **Tool descriptions**: Include routing keywords + context hints (searches on tool name, description, arg names/descriptions)
- **Server instructions**: Provide high-level workflows, but **truncated silently** when multiple servers exist — unreliable for critical routing
- **Attached skills/docs** (ctxlayer model): Org-curated playbooks attached to specific upstreams/tools; avoids relying on model memory of instructions
- **System prompt steering**: Light prompt like "consult the playbook before using tool X" increases likelihood but doesn't guarantee behavior

**No evidence of:**
- A "skills" or "workflow hints" structure beyond the `instructions` field
- Anthropic guidance on avoiding Desktop's instruction-truncation problem
- Detection of prompt injection from tool-description text (Desktop doesn't flag instruction-like descriptions as risky)
