## 1. Open security items

Ranked. None are known-exploited; all were verified by reading the code.

### 1b. Destructive GET, no origin check
`api/upstream-oauth.ts` — `GET /:id/oauth/start` is `requireUser`-only (correct
for a redirect endpoint) but two inner branches call `deleteUserCredential`.
An attacker page can force the navigation; `SameSite=Lax` does not stop a
top-level one. Narrow in practice (the wipe only fires when the stored refresh
token is already broken), so this is DoS-shaped, not theft.
**Fix:** an `isAllowedOrigin`/`Sec-Fetch-Site` check on the route, or move the
wipe behind a POST.

### 1c. Redirects carry the Authorization header
`git/provider-util.ts` — `assertSafeFetchUrl(input.url)` validates hop 0 only;
`fetch` then follows redirects by default with `input.headers` (carrying the
PAT) attached. Whether workerd strips `Authorization` cross-origin is a runtime
detail this repo neither asserts nor tests. Requires a compromised or
self-hosted git host to exploit — `base_url` is admin-set and https-validated.
**Fix:** `redirect: 'manual'` + re-assert per hop. Same shape in
`upstream/http-client.ts`.

### 1d. No response-size guard on git fetches
`git/provider-util.ts` — `await res.text()` is unbounded, while the upstream
proxy caps at `UPSTREAM_MAX_RESPONSE_BYTES` (256 KiB). A large blob/tree from a
synced repo buffers fully in worker memory. `git/gitlab.ts` caps page *count*,
not per-response bytes.

### 1f. Lower
- 5 pre-admission failure branches per IdP skip `clearStateCookie()`
  (`idp/google.ts`, `idp/github.ts`). All *completion* paths are covered, so
  this is hygiene — but CLAUDE.md says "every completion path".
- `auth/cf-access.ts` — a `kid` miss forces a JWKS refetch with no negative
  caching or rate limit. Cheap claim checks pass without a signature, so an
  unauthenticated flood of random `kid`s drives one outbound fetch per request.
  Only reachable when `accessTrustConfigured(env)`.

  tests for shared yet'"`. Highest value, all pure functions:

  ~6 sites deliberately under-declare deps (with comments); `"warn"` + those

## 4. Product decisions

- **`skill_tags` is a write-never table.** The only `INSERT` is the historical
  backfill in `0026_topic_to_tag.sql`; no application code writes it. So
  `listTagsForSkill` always returns `{teams:[],products:[],tags:[]}`, costs a D1
  round trip per skill-detail fetch, and lands in a response field no SPA or MCP
  consumer reads. Either wire up skill tagging or drop the concept (query +
  response field; leave the table).
- **`documents.kind` is dead end-to-end.** Written, read, serialised, consumed by
  nobody — no `apps/web` file reads `doc.kind`. Removing it from the two SELECT
  lists, the row/input interfaces, `toSummary`, and the three shared schema
  fields is safe; the SQLite column should stay (dropping a referenced parent
  needs the G1 detach/swap/reattach dance).
- **`wrangler.toml` commits real `database_id` + OAUTH_KV `id`.** Left alone:
  they are `ctxlayer-*` infra, not tenant-specific, and zeroing them breaks the
  canonical deploy. The binding comment now documents how to zero them for a
  fork.
